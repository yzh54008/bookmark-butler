    这个插件是怎么「聪明」起来的
    
      
    它不会内置一套写死的分类，而是把你的书签按域名聚合成一份摘要，交给你自己配置的大模型，让模型归纳出贴合你的目录体系，再逐层分派。三阶段：
    
      
      
        
    1. 归纳体系：模型只看聚合摘要（域名 + 条数 + 标题样本），产出 6~14 个一级目录及子目录。
      2. 
        
    2. 域名分派：把每个域名指到一条路径上。几百条书签通常只有一百来个域名，这一步决定了整体质量。
      3. 
        
    3. 逐条细判：只对「一个网站多种用途」的情况（比如同一个站点既有卖家后台又有商品类目页）才逐条判断。
      4. 
      
    
      
    最后一步还有兜底：模型没覆盖到的，交给本地规则引擎；两者都定不了的，进 99 · 待整理，绝不乱放。
    
    
    

    
    
      
    把插件分享给朋友
    
      
      
        
    1. 把插件文件夹打包（不要把 dev/ 目录一起给出，那里面可能含有你的真实书签样例）。
      2. 
        
    2. 对方解压后，打开 edge://extensions（Chrome 是 chrome://extensions）。
      3. 
        
    3. 打开右下角的开发者模式，点加载解压缩的扩展，选择解压出来的文件夹。
      4. 
        
    4. 点插件图标 → 打开 AI 智能整理 → 模型配置 → 填对方自己的 API Key → 保存。
      5. 
        
    5. 回到「整理向导」，一路点下去即可。
      6. 
      
    
      
    对方的 Key 只存在对方电脑上。你不需要、也不应该把自己的 Key 给别人。
    
    
    

    
    
      
    安全边界（请确认你接受）
    
      
      
        
    • 整理过程只移动书签，从不删除。用错了随时点「撤销本次整理」。
      • 
        
    • 默认只把域名和标题发给模型；不发送书签里没有的东西，也不读取浏览历史、Cookie、密码。
      • 
        
    • API Key 存在 chrome.storage.local，不参与浏览器账号同步，不会随账号上传云端。
      • 
        
    • 插件除了你自己配置的那个模型端点之外，不向任何服务器发送数据。
      • 
        
    • 插件申请的权限：bookmarks（读写收藏夹）、storage（存配置与备注）、
            以及对模型端点的访问权限（首次配置自定义端点时会弹窗询问）。

    常见问题
    
      
    
        
    提示「鉴权失败 401」
    
        
    Key 不对、已过期，或复制时带了空格。重新粘贴一次；有些服务商需要先在后台开通对应模型。
    
        
    提示「接口或模型不存在 404」
    
        
    Base URL 没填对。多数服务商要写到 /v1（通义千问必须用「兼容模式」的地址）。
    
        
    提示「触发限流 429」
    
        
    把「并发请求数」改成 1，或把「每批域名数」调小，稍后重试。
    
        
    整理出来的目录不满意
    
        
    先在「业务背景」里把自己的工作写具体，再重新生成。也可以点「尽量沿用我现有的顶层目录名」。
    
        
    不想花钱 / 不想把数据发出去
    
        
    用本地的 Ollama：装好 Ollama、ollama pull qwen2.5:7b，服务商选「本地 Ollama」即可，数据不出本机。
    
        
    整理完想还原
    
        
    页面底部有「撤销本次整理」，可恢复到移动之前的状态（含清理掉本次新建的空目录）。
